## 1. `Object::AddRef` / `Object::Release` — the caller census said "free", and it was right

**Identity, on retail bytes.** `0x8275bd08` loads `r4`'s vtable, calls slot 1
through the `ctr`, and on a nonzero result inserts into the list at `this+0x20`;
`0x8275b378` makes the same virtual call, then walks that list comparing
`node+8` / following `node+0`, and erases. Symmetric insert/erase on one member
is `AddRef(ObjRefOwner*)` / `Release(ObjRefOwner*)` over Object's ObjRef
registry, and nothing else in Milo has that shape. The virtual call on `r4`
independently corroborates the **`ObjRefOwner`** parameter that our spelling
carries.

**The spelling is unanimous, which kills most of the feared exposure a priori.**
Exactly one spelling of each exists anywhere in the build
(`?AddRef@Object@Hmx@@QAAXPAVObjRefOwner@@@Z` in 341 objs, `?Release@…` in 368;
both **defined only in `Object.obj`**). So no caller *can* spell it differently.

**The census** — 196 + 268 = **464** retail `bl` sites, keyed on retail `.pdata`
extents → map name → report row **by name**, i.e. the way objdiff actually pairs:

| | AddRef | Release |
|---|---:|---:|
| retail `bl` sites | 196 | 268 |
| in a `.pdata` gap | 0 | 0 |
| enclosing fn unnamed in map (⇒ placeholder row, 0 %) | 111 | 98 |
| distinct named **and paired** enclosing rows | 81 | 163 |
| …of those, at `fuzzy == 100` (**nominal exposure**) | 60 rows / 13,436 B | 151 rows / 27,440 B |
| …at `fuzzy < 100` (no downside) | 21 | 12 |

⇒ real exposure **0 B**, which is what the A/B then measured.

## 9. Reusable lessons

* **`classes_installed_by` is a positive-only instrument** — an absence is not
  evidence, because the body also stores *member* and *base* subobject vtables.
  Two rows "installing" the same class is the tell.
* **Retail fan-in separates a transposition from an ICF fold**, and it is cheap:
  fan-in 1 ⇒ exclusive callee ⇒ a wrong name is possible; fan-in ≫ 1 ⇒ shared
  survivor ⇒ refuse.
* **A closed permutation cycle is a self-validating repair.** It only closes if
  every member's reading is right, and it preserves injectivity for free.
* **Price a map rename through the pairability gate first.** Three of the best-
  evidenced repairs in this lane were worth 0 or refused *for that reason alone*,
  independent of how good the identification was.
* **A unanimous result is the vacuity signature.** Three times here (0/464 sites,
  67/67 SUSPECT, 0/N `owner()` hits) a decisive-looking answer was an instrument
  defect. Each was caught by a control, never by inspection.
