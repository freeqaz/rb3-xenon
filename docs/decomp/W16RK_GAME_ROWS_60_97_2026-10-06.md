# W16-RK — fifteen RB3 game-layer rows between 60% and 97% fuzzy (2026-10-06)

Branch `w16-rk`, base `1beb30e28`. The fifteen rows were split by source file
across seven forks (`w16-rk-a` … `w16-rk-g`), each in its own worktree, and the
fork branches were merged into `w16-rk` with `--no-ff`. Every score below is
`fuzzy_match_percent` / `match_percent_normalized` on the shipped `name_check`
ruler, read from the **A/B leg reports** (`legA_report.json.gz` and
`legB_report.json.gz` of the run cited at the end), not from fork-local builds.

## Result

**Whole binary (`tools/ab_measure.py --patch`, combined diff `1beb30e28..w16-rk`):
Δmatched +8, Δcode_bytes +5,228, Δcode% +0.051013 pp, Δfuzzy +0.008924 pp,
units at 100 % (mpn) 590 → 594, 0 units fell off.**

Prediction before the run: +5,228 B from the six rows that reached fuzzy 100
(456 + 228 + 400 + 332 + 424 + 3,388), and roughly +8 functions once the two
mpn-only crossings are added. It came out exactly. The one row outside the list
that moved is `WorkVerts::SetVertsAndFaces` (940 B), from 99.000 / 99.149 to
99.957 / 100. That is the second mpn-only crossing.

## What closed the rows that reached 100

- **SaveLoadManager::OnMsg(MCResultMsg).** The logic already matched. Retail
  lowers the outer switch as a binary tree pivoting on 0x47, and ours lowered it
  as a compare chain. Spelling the `default:` as `MILO_FAIL_RTL` keeps the
  default block distinct from the `break` exit while the switch is lowered,
  which yields the tree. On the native build `MILO_FAIL_RTL` expands to
  `MILO_FAIL` (`os/Debug.h:203`), so behaviour is unchanged.
- **BandList::UpdateConcealState.** Three `ForceConcealed` call sites are
  merged into one. Retail keeps the first, and our if/else-if chain kept the
  last. Rewritten as early returns, the same style as its neighbour
  `UpdateRevealState`.
- **MultiplayerAnalyzer::AddGems.** Reading the vector through a local
  `std::vector<GemScore> &scores` reproduces retail's reload of the start
  pointer after the `mMaxPts` store.
- **OverdriveMeter::SyncObjects.** The earlier Sonnet AT_LIMIT is refuted. With
  nine `mX = Find<T>()` statements, the inline `ObjPtr::operator=` layer pushes
  the block over a scheduling threshold and hoists `mr r3`. Calling
  `SetObjConcrete` directly, which is exactly what `operator=` does, gives
  retail's `li r5 / addi r4 / mr r3` on all nine calls. The shared `Object.h`
  is untouched.
- **BandLeadMeter::SyncScores.** Writing `int dir = neg > 0 ? 1 : -1;` gives
  retail's two separate int-to-float stack slots. Fourteen respellings of the
  ratio expression were byte-identical.
- **VocalPlayer::Poll.** Two earlier AT_LIMIT/STUCK verdicts are refuted, and
  every residual turned out to be a source shape:
  - three inline accessors whose return values retail stores to a stack slot
    (`VocalPart::GetFrameMatchType`, `Singer::GetBestTargetPitch`,
    `Singer::GetLastFrameMicEnergy`; no layout change);
  - both vector sizes taken into int locals for the loop test;
  - declarations moved to retail's initialisation points;
  - `remove_if` results named before `erase`;
  - `fabsf` on both sides of the deviation compare.

## Stuck reasons

- **CharKeyHandMidi::Poll (92.841).** Three changes raised it: the `IsBlackKey`
  branch first, the `-0.4*up` product kept separate so it is not fused into an
  `fmadd` (`#pragma fp_contract(off)` does not stop an inline `a*b + c`), and
  the tip vector built from the `cur` registers.
  - **Residue:** 120 instructions of floating-point scheduling and register
    order in the key-layout block, plus four `lwzx` base/index operand swaps in
    inlined vector code. This is permuter class, which is deferred by directive.
  - **Frame-size trap:** variants that grow the frame from 0x140 to 0x150 read
    up to 94.5 on the row, but break the 40 B unwind row `fn_822D21BC`, so they
    were rejected.
  - **Withdrawn alias:** the fork also added two `symbol_aliases.json`
    memberships (`FingerNum` `__find` / `push_back`). The coordinator reverted
    them before merge (`ca041a844`). They were worth +0.018 pp on a row far
    below 100, which is 0 B, and the `__find` membership pairs COMDATs of
    different sizes (176 vs 172 B). An alias is forgiveness, so it should land
    only where it pays and the fold is beyond doubt.
- **BandPatchMesh::FindXfm (77.968).**
  - **What raised it:** the normals now live as a `Vector3[3]` in a block scope
    passed to `Multiply` as a Matrix3, which reproduces retail's shared stack
    slot 0x50 and frame 0x200. The axis copies are moved earlier.
  - **Residue:** retail loads posOut's rows straight into f26–f31, and ours
    loads them via scratch registers plus six `fmr`. The prior Opus attempt hit
    the same wall. Retail also loads all eight pos/norm words before storing.
- **BandPatchMesh::WorkVerts::ExtendTwin (85.235).**
  - **What raised it:** `Invert(Matrix2)` declared `inline __declspec(noinline)`.
    It is still called out of line, but the compiler stops using its knowledge
    of which registers Invert clobbers. This also lifted `SetVertsAndFaces` to
    mpn 100.
  - **Residue:** retail reloads outDir.x/.y from memory after the call, and
    ours keeps .y in f31. There are two dead `fmr`s, and the rest is operand
    order and scheduling.
- **BandPatchMesh::WorkVerts::TryAddFace (90.956).**
  - **What raised it:** reading the uv values through the MeshVert pointers.
  - **Residue:** retail recomputes the y edge and reloads pb/pn/pp without
    reuse. Every local and reference variant tried was neutral or worse.
- **GemTrack::DrawFill (88.797, no change).** All 50 charged sites come from one
  block-placement decision. Both builds merge the two `FillsEnabled()` calls.
  Retail keeps the copy in the non-trainer arm and moves the trainer arm out of
  line; ours keeps the copy in the later source arm.
  - **Variants:** the RB3 game source's early-return form (88.35), swapped arms (88.35,
    with a byte-identical but inline trainer block), and swapped arms with a
    nested-if `b9` (88.1). A `goto` was byte-identical, because control flow is
    normalised before layout.
  - **Verdict:** permuter class.
- **VocalTrack::UpdateTambourineGems (87.215, no change).** The fall from the
  recorded 91.23 is **not a code regression**:
  - **Evidence:** the body has been unchanged since June, and the headers it
    uses changed only in comments since July. Both sides still have the
    identical 186-opcode multiset. objdiff now pairs the moved loads as
    inserts and deletes on the `name_check` ruler (2026-08-12), and every
    reading since 09-30 is 87.215.
  - **Residue:** load scheduling inside three inlined `deque::size()` calls.
  - **Tried:** dropping the `gems` reference (81.87) and an unsigned index
    (no change).
- **ChordShapeGenerator::InterpolateXfm (97.418).**
  - **What raised it:** in each branch, reading the endpoints through a local
    `const Vector3 &` before the in-place ops on `out.v`.
  - **Residue:** 15 of 197 instructions. Two `fadds` have their operands the
    other way round; in the second branch retail stores z and y before x and
    keeps `out.v.z` live instead of reloading it.
  - **Tried:** eleven other variants scored worse or the same. The RB3
    game source's `out.v.Set(...)` form scored 68.96.
- **NoteTube::CreateMeshes (99.898, mpn 100).** References `first`/`last` in the
  `numpoints > 2` branch stop `begin()` being hoisted above the `== 2` split.
  - **Residue:** one commutative swap, retail `fadds f13,f0,f11` against ours
    `fadds f13,f11,f0`. About 20 spellings left it unchanged, so the operand
    order follows the order the compiler creates values in, not source order.
- **VocalPart::CalcPhraseScoreMax (76.958 / 81.229).** Reading the loop bound
  through the phrase (`i != p->unk14`) reproduces retail's `cmplw`/`bne`
  counter loop instead of `mtctr`/`bdnz`.
  - **Trade-off:** fuzzy +0.21 and mpn −0.83. It was kept because the loop
    shape is now retail's, and neither ruler is at 100, so `matched_code` is
    unaffected. Reverting it is one hunk.
  - **Residue:** retail reloads `phrase->unk0`, `phrase->unk4` and
    `note.mDurationMs` every iteration. A static helper knocked a sibling row
    off 100 and was reverted.
