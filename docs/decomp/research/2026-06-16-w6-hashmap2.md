### Function identification evidence

**GetSongsInContent** (`fn_827841B0`, 70.3%): already named in `target_symbol_map.json`.
Body: find in mSongIDsInContent, if found assign `it->second` to vec arg. Matches source.

**ContentNameRoot** (`fn_82784268`, 0%): reads `node+0x10` = `String._Mstr` (the
`char*` field of the String value). String layout: `{vptr@0x8, mCap@0xC, mStr@0x10}`.
Returns `it->second.c_str()` from unkmap5. Confirmed by dc3:
```cpp
char const *SongMgr::ContentNameRoot(Symbol contentName) const {
    auto it = unkmap5.find(contentName);
    if (it == unkmap5.end()) return nullptr;
    else return it->second.c_str();
}
```

**NumSongsInContent** (`fn_827842B0`, 0%): after find at 0x70, reads
`node+0x8` (vector._M_begin) and `node+0xC` (vector._M_end), computes
`(end-begin)>>2` = `vector<int>::size()`. Then returns 0 on miss. Matches:
```cpp
int SongMgr::NumSongsInContent(Symbol contentName) const {
    auto it = mSongIDsInContent.find(contentName);
    if (it != mSongIDsInContent.end()) return it->second.size();
    else return 0;
```


**ClearFromCache** (`fn_827847D0`, 0%): stw r4 (Symbol arg) to stack, addi r31=r3+0x70,

```cpp
void SongMgr::ClearFromCache(Symbol contentName) {
```

## Finding 2: PhysicsVolume — NO-GO, calls fn_82543F88+0x80 (different helper)

```
grep "fn_82543F88" build/45410914/asm/PhysicsVolume.s
→ 3 occurrences, all `bl fn_82543F88+0x80`
```

`fn_82543F88+0x80` = address `0x82544008`. The body at that offset is:
```
/* 82544008 */  lwz r3, 0x8(r3)
/* 8254400C */  b fn_82797AA0      ← 48 25 3A 94 = b to 0x82797AA0
```
This is a **thunk** embedded inside the ICF-merged COMDAT, NOT the hash_map find
entry point. The three PhysicsVolume callers pass `addi r3, r31, 0x50` (a local
object field), load `r3->field_8`, and jump to `fn_82797AA0`. This is a destructor
or clear call — unrelated to hash_map. **No hash_map fix applies.**
