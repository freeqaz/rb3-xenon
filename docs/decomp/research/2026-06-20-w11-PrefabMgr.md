## WRINKLE #1 — BinDiff oracle mislocated PrefabMgr (blocks the auto map gen)

`unified_id_rb3wii.json` has 30 PrefabMgr/PrefabChar entries, but their
`rb3_addr` values are **scattered** (0x8226c630, 0x82376800, 0x8237d088,
0x8247cfc8, …) — none fall in the real cluster `[0x82540840,0x825426A0)`. These
are BinDiff structural false-positives (the project's documented oracle-FP risk).
`tools/gen_game_target_map.py` keys on `e["rb3_addr"]` and span-filters
(lines 317-322), so `--tu PrefabMgr.cpp` would emit **all out_of_span → 0 entries**
for our cluster. The auto-mapper cannot wire this TU from the broken oracle.

**Mitigation (in the plan):** build the addr→mangled map for the cluster by
compiling PrefabMgr.obj and pairing its *defined* MSVC symbols to cluster
`fn_<addr>` by **structure** (size + call-graph + string xrefs), seeding the
identity anchors already established here (ctor/dtor/Handle/getters). This is the
same class/method+arity pairing gen_game_target_map does, just seeded with the
correct span+identity instead of the oracle's wrong addresses.
