## 1. Premise correction (read before spending effort on the DirLoader-pinned five)

objdiff pairing is **per-unit**: each unit pairs the dtk target obj against exactly one compiled
base obj (`objdiff.json`: `default/DirLoader` → base `build/45410914/src/system/obj/DirLoader.obj`).
A symbol defined in our `Object.obj` can never pair inside the `default/DirLoader` unit.

## 2. The two fixable targets

### 2a. `??0Object@Hmx@@QAA@XZ` — report-norm **74.58**, tgt 96B vs base 80B → FIXABLE (+1)

`run_objdiff(unit="default/Object")` decisive diff: retail has **4 extra instructions** building
an 8-byte zero on the stack and copying it into `mRefs` (offset 0x20) *before* the self-loop
stores; ours goes straight to the self-loop:

```
tgt:  subi r7, r1, 0x10        (ours: —)
tgt:  std  r11, 0x0, r7        ; store 64-bit zero to stack temp
tgt:  ld   r7, -0x10, r1       ; reload
tgt:  std  r7, 0x20, r3        ; copy 8-byte zero into mRefs{next,prev}
tgt:  stw  r10, 0x20, r3       ; then self-loop next = &mRefs
tgt:  stw  r10, 0x24, r3       ;           prev = &mRefs
```

That is the MSVC X360 idiom for **copy from a zero temporary `ObjRef()`** (8-byte non-polymorphic
X360 ObjRef `{next@0, prev@4}`, no user ctor — Object.h X360 branch, `OBJREF_VIRTUAL` empty).
Remaining mismatches are the r10↔r11 register cascade from the missing instructions, plus two
`subi`-vs-`addi` vtable materializations (`subi r9,r11,0x1174` = `??_7Object@Hmx@@6B@`,
`subi r7,r10,0x19b4` = `??_7TypeProps@@6B@`) where dtk attached no reloc (cross-register lis/subi
pair, raw bytes `39 2B EE 8C` in `build/45410914/asm/Object.s:21`).

**Reloc-noise wall test — PASSED (not a wall):** scanned all pinned-unit asm for the same raw
cross-reg lis/subi pattern and joined against report-normalized: `?DestroyMCFile@MCContainer@@...`
(default/Memcard, raw subi @0x8252018C) and `fn_82391444` (default/CharBoneOffset, @0x823913DC)
both sit at **norm 100.0** containing it. The artifact normalizes once registers align.

**Fix (Object.cpp body-only, X360 `#else` branch of the ctor):** make the retail branch
zero-copy mRefs before DetachSelf. Try in order, A/B each:
1. body: `mRefs = ObjRef();` immediately before `mRefs.DetachSelf();`  (copy-from-temp — most
   likely to emit the std/ld stack round-trip)
2. init list: append `, mRefs()` (value-init; runs last in member order = matches the position
   of the zero stores after the `mDir`/`mNote` stores)

### 2b. `??1Object@Hmx@@UAA@XZ` — report-norm **64.62**, tgt 272B vs base 208B → FIXABLE (+1)

Gate-zero passed: base reg is genuine `this` (`mr r30, r3`), not a funclet frame; every divergent
`bl` callee is identified and accounted (no FUNCLET_PAIRING tell). Five source deltas, ALL
confined to the dtor body (retail/`#else` branch, `Object.cpp:167-200`):

1. **Missing `MainThread()` call.** Target: `bl ?MainThread@@YA_NXZ` immediately after the vptr
   store; result ignored (no compare). Our `MILO_ASSERT_FMT` retail expansion is
   `((void)sizeof(!(cond)))` (Debug.h:119) = **unevaluated**, so the call vanished. Retail
   evaluated the cond. Fix locally: insert `(void)MainThread(); // retail evaluates the
   MILO_ASSERT_FMT cond` before the existing macro line. (Do NOT flip the macro globally in this
   lane: 50 uses / 22 files, header ripple; see §4.) Confirms the knock-on `lwz r3, 0x10(r30)`
   vs ours `0x10(r3)` — after a call, `this` must come from r30.
2. **Extra early `ClearAllTypeProps()`.** Base-only `bl ?ClearAll@TypeProps@@AAAXXZ` (3 inserts,
   idx16-18); retail has no early ClearAll — only the tail `~TypeProps` (`bl fn_82263E30`, pairs
   with our `??1TypeProps@@UAA@XZ`, reloc-normalized equal). Remove the `ClearAllTypeProps();`
   line. Semantically safe: `~TypeProps() { ClearAll(); }` (Object.h) runs at the end either way.
   Side effect: frees a callee-save reg → prologue `__savegprlr_25` becomes retail's
   `__savegprlr_26`.
3. **Ring-walk loop shape: advance-before-call.** Retail: `mr r11,r29; lwz r29,0x0(r29)` (save
   cur, advance) then `lwz r3,0x8(r11)` (RefPtrOf) and vcall slot 0x8; ours dereferences then
   advances after the bctrl. Rewrite:
   ```cpp
   ObjRef *it = mRefs.next;
   while (it != &mRefs) {
       ObjRef *cur = it;
       it = it->next;
       RefPtrOf(cur)->Replace(reinterpret_cast<ObjRef *>(this), nullptr);
   }
   ```
4. **Missing mName free block** (the big one — 8-instr delete cluster idx 47-54 + `bl
   fn_82798278`). Retail, after restoring `sDeleting`:
   ```
   lwz r4, 0x14(r30)            ; mName
   lwz r11, gNullStr            ; (lbl_82C411B0)
   cmplw cr6, r4, r11 ; beq skip
   <inlined strlen scan: lbz/addi/cmplwi/bne; subf; subi 1; clrrwi 0>
   addi r3, r11, 0x1            ; strlen(mName)+1
   bl   fn_82798278             ; (size, ptr)
   ```
   `fn_82798278` disassembled (MemHeap.s): `if (!r4) return; if (r3 > 0x80) tail fn_82797AA0(ptr)
   else tail fn_82795DA0(size,ptr)` — that is exactly our 2-arg
   **`PoolFree(int, void*)`** (`src/system/utl/PoolAlloc.h:80`; small-pool with >0x80 heap
   fallback), the same helper our Object.cpp already uses for ring nodes. Fix:
   ```cpp
   if (mName != gNullStr) {
       PoolFree(strlen(mName) + 1, (void *)mName);
   }
   ```
   placed right after `sDeleting = old;`. `strlen` inlines under `/Oi`. Semantic verification =
   the retail binary itself (RB3-retail owns a pooled copy of mName; neither DC3 nor rb3-Wii has
   this block — rb3-Wii's dtor confirms no Wii-era equivalent, `../rb3/src/system/obj/
   Object.cpp:108` — so this is RB3-360-specific and the asm is the only and sufficient oracle).
   The block lives in the retail-only `#else` branch which no runnable build executes.
   If the no-op `clrrwi r11,r11,0` doesn't appear, try `(int)strlen(...)` / an intermediate
   `int len = strlen(mName);` — cosmetic intrinsic-tail variance.
5. **`ObjRingFree(&mRefs)` position.** Retail frees the ring AFTER the `gDataThis` check
   (member-dtor position: `mr r3,r27; bl 0x82451A48` where the map names that address
   `_List_base<ObjectDir*>::clear` — an ICF twin of ring-free; reloc-normalized equal vs our
   `bl ?ObjRingFree@@YAXPAVObjRef@@@Z`). Ours calls it before. Move the call below the
   `if (gDataThis == this)` block, making it the last statement.

Residual risk: target spills `stw r27, 0x50(r31)` (&mRefs) twice; expected to fall out of the
changed register pressure, else permuter-class cleanup on a ~95% body. Sizes reconcile:
272−208 = 64B ≈ +mName block (~60B) +MainThread (4B) −early-ClearAll (12B) +spills.
