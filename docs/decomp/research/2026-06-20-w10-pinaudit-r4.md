## Tooling note (for a separate tool-fix item, NOT foundational)

`pin_audit.py`'s candidate `pin` field reflects only the **last** .text range of
a multi-range unit, producing phantom "second cluster" candidates (Part,
PropKeys this round) whose proposed range is already covered by an earlier
range. A cheap fix: have pin_audit subtract ALL of a unit's existing .text
ranges before reporting a cluster as under-pinned. This is a read-only tool
improvement, not a binary lever — left for the coordinator's tooling queue.
