## A. `?FinishSelecting@UIComponent@@AAAXXZ` — FIXABLE, +1, root cause = header tail-byte layout

Report-normalized **99.97938** (= diff score 2/9700 exactly), size 388.
⚠️ Live objdiff prints "100.0% normalized" — that is display rounding
(99.979→100.0); report-normalized is <100, so this fn is NOT counted. Not the
vtable/reloc +0 trap: the two scoring diffs are *member-offset* diff_args, not
relocations.

The complete normalized diff (run_objdiff full_listing, 2026-06-11):

```
idx 15  target: lbz r11, 0x13d, r30     base: lbz r11, 0x13c, r30   diff_arg
idx 94  target: stb r11, 0x13d, r30     base: stb r11, 0x13c, r30   diff_arg
```

(The `bl ?Node@DataArray@@QAAAAVDataNode@@H@Z` vs `bl ??4DataNode@@QAAAAV0@ABV0@@Z`
pairs at idx 50/69 are reloc-target-only and are ignored by normalized scoring
on BOTH report and live — do not chase them.)

So retail keeps `mSelectCancelled` at **0x13d**; our header
(`src/system/ui/UIComponent.h:114-116`) has:

```cpp
unsigned char mSelectCancelled; // 0x13c   ← wrong
bool mLoading;                  // 0x13d   ← wrong
bool mMockSelect;               // 0x13e   ← does not exist on retail
```

### Retail tail layout — proven from three independent target fns (`build/45410914/asm/UIComponent.s`)

1. **fn_827D9010 = `MockSelect()`** (Wii oracle `../rb3/src/system/ui/UIComponent.cpp:224-230`):
   `lwz r11, sSelectFrames; stw r11, 0x104(r3)` (mSelected, asserts stripped),
   vcall slot 0x34 r4=3 (`SetState(kSelecting)`), then
   `li r11,1; stb r11, 0x13d(r31)` — Wii's `mMockSelect = true` → **0x13d is
   the select-flag byte**.
2. **fn_827D9060 = `UpdateResource()`** (Wii cpp:374-382): `lwz r3,0x108(r3)`
   (mResource) → `bl fn_827FDEE8` (UIResource::Release); `TheUI`
   (lbl_82C41B48) + `bl fn_827E0428` (UIManager::Resource(this)) → `stw r3,
   0x108`; **`lbz r4, 0x13c(r31)`** → `bl fn_827FDE78` =
   `mResource->Load(mLoading)`; **`lbz r11, 0x13c`** + gResettingType
   (lbl_82DA0017+0x35FB9) + vcall slot **0x4c** (`Update()`) — → **0x13c =
   mLoading**, twice.
3. **ctor fn_827DA5B0** zero-stores exactly TWO tail bytes:
   `stb r29, 0x13c; stb r29, 0x13d` (asm @827DA78C/827DA790). There is no
   third flag byte; `grep 0x13[ef]` over the unit asm = zero hits.

Conclusion: retail RB3-360 has Wii's model — `bool mLoading; // 0x13c` then a
**single** flag `// 0x13d` that `MockSelect()` sets and `FinishSelecting()`
tests+clears (Wii names it `mMockSelect`, DC3/our cpp name it
`mSelectCancelled` — `../dc3-decomp/src/system/ui/UIComponent.cpp:145,151`
confirms DC3's FinishSelecting uses mSelectCancelled the same way). Our header
wrongly split it into two members (mSelectCancelled + mMockSelect) and put
mLoading second.

### Edit

`src/system/ui/UIComponent.h:114-116` →

```cpp
bool mLoading;                  // 0x13c
unsigned char mSelectCancelled; // 0x13d — Wii name mMockSelect, same byte:
                                // MockSelect() sets it, FinishSelecting() tests+clears
// (no third flag; 0x13e/0x13f = padding)
```

and `src/system/ui/UIComponent.cpp:32-36` ctor init-list: drop `mMockSelect(0)`,
order `mLoading(0), mSelectCancelled(0)` (decl order = store order; retail ctor
stores 0x13c then 0x13d).

Blast radius: `grep -rn "Loading()\|mSelectCancelled\|mMockSelect" src/`
excluding this TU = **zero UIComponent users** (all hits are unrelated
PollForLoading/IsLoading etc.). Still a header edit → full-binary A/B is
mandatory per hard rule.
