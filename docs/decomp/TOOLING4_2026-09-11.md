## Item 1 — both importers discarded the now-charged `Symbol` args

### Mechanism

`tools/shape_families.py` and `tools/structural_decompose.py` build an instruction
"shape" from objdiff's `typed_args` and both **dropped the `Symbol` (relocation)
args**, justified as "masked by `functionRelocDiffs=none`". That premise died with
`d04c83df` (2026-08-12) and became load-bearing with `d1b4f708`, which put
`crossing_worklist` — the module that *feeds* both — on the graded ruler at
runtime. Lane SCRIPT-ROT (`009ea365`) documented both in place and deliberately
left them unfixed because changing either key changes every ranking.

**The brief said the wrong-callee class was *invisible* to both rankers. The
measurement says something worse: it was *present and misrendered*, and it had
taken over the top of the ranking.**

Measured at `3ab3f494`: **1,982 of 3,226** sub-100 rows (**61.4%**) / **461,400 B**
(**42.6%**) carry *nothing but* relocation-name charges. Under `none` such a row
renders as zero mismatches and was dropped by `if not sig: continue`. So the ruler
flip **injected the entire wrong-callee class into the population**, where a
dropped `Symbol` made every one of them render as a bare `bl` on *both* sides.

⇒ Three of `shape_families`' five controls were **RED ON ARRIVAL**:

| control | before | after |
|---|---|---|
| 3 — largest family is not the whole population | **FAIL** 1387/2458 | PASS 21/2458 |
| 4 — enrichment over permutation null | **FAIL** 1.30x | PASS 241.72x (scoped) |
| 5 — no BLIND shape spans ≥2 rows | **FAIL** 9 shapes, largest in 2,461 rows | PASS 0 |

`structural_decompose --selftest` was red too (rc=1), for an unrelated reason —
see its own section.

### Ground truth on the arg types

Census over 4,000 cached diffs. objdiff emits **exactly** `Register`, `Symbol`,
`Signed`, `BranchDest`, `Other`, `Unsigned`. **`Opaque` occurs zero times.**

So `structural_decompose.key()`'s tuple `('Register','Signed','Unsigned','Opaque')`
silently discarded **three live kinds, not one**: `Symbol`, `Other` (where shift
and mask amounts live, e.g. `{'type':'Other','value':'24'}` on `clrlwi.`) and
`BranchDest`.

### Fix — literal names, and the obvious alternative measured and rejected

The design question is not *whether* to admit `Symbol` but *how*, because the
surviving rationale for excluding it was real: one defect replicated across
template instantiations must still group into one family, which is what the tool
exists to detect. Three candidates, measured on the same rows:

| treatment | sigs | families | biggest family | blind shapes ≥2 rows |
|---|---|---|---|---|
| drop `Symbol` (shipped) | 451 | 37 | **1387 (56.4%)** | 5 |
| placeholder-normalise (`@0`/`@1`) | 451 | 37 | **1387 (56.4%)** | 0 |
| **literal names (chosen)** | 1959 | 232 | **21 (0.9%)** | 0 |

⚠ **Placeholder normalisation — the device `regnorm` already uses for registers —
repairs CONTROL 5 and leaves the artifact family exactly intact**, because every
"target calls something, base calls something else" `bl` still renders
identically. It fixes the symptom the control names and not the defect. This is
the trap worth remembering: the control that fires is not always pointing at the
thing that must change.

**And the standing objection to literal names is refuted by measurement on this
population**: the old key's *genuine* (non-artifact) families cover **657** rows
(2,044 − 1,387 artifact); literal names cover **731** rows in 232 families.
Literal finds *more* real structure, not less, because a wrong-callee row's defect
**is** the callee pair, and that pair is the unit of one fix.

The two tools get the same admission for **different reasons**, and that
distinction is the intellectual core of the item:

* `shape_families` groups **across rows** → had to weigh instantiation
  fragmentation → measured, literal wins.
* `structural_decompose.key()` feeds only `transposed_pairs`, which compares two
  instructions **within one row** and asks "is this the same instruction, moved?"
  If retail calls `Foo` and we call `Bar`, they are not the same instruction, so
  the literal name *is* the question.

⚠ Deliberate asymmetry recorded at `key()`: a folded-alias callee now reads as a
genuine divergence rather than as scheduling. That is the safe direction — it
routes the row to a human instead of dismissing it — and it is the direction
CLAUDE.md asks for, since objdiff cannot separate `folded` from `wrong`.

### Two instrument defects fixed alongside, both of the "cannot discriminate" family

**1. `assert buckets['ALL'] > 0` asserted a property of the POPULATION, not the
tool.** It could not distinguish a broken detector from a population with no
transpositions left — and it was **already failing for the second reason** on
arrival (0 ALL / 0 SOME / 79 NONE). *A control that goes red when the work
succeeds teaches lanes to ignore it.* Replaced by the fixtures above; the live
buckets are still printed, as information.

⚠ Consequence stated plainly: **`structural_decompose`'s live output is
byte-identical before and after this lane** (79 rows / 15,608 B, 0/0/79, same
14-shape composition), because its transposed count was already 0 and admitting
arg kinds can only reduce it. **The fixtures are the only evidence its fix bites.**
This is a latent-correctness fix, not a ranking change.

**2. Control 4 was scoped and self-calibrated — and this is not the bar being
moved to let the change pass.** Two independent faults:

*(a) the null is vacuous — and biased — on mm==1 rows, which are 69.7% of the
population.* `cmd_null` rebuilds a signature by drawing shapes independently from
the global pool, i.e. it destroys **which shapes co-occur in a row**. A one-shape
row has no co-occurrence to destroy, so the null draws from the same marginal the
observed shape came from and is testing a distribution against itself:

| subpopulation | n | observed | null | enrichment |
|---|---|---|---|---|
| mm==1 | 1713 | 151,856 B | 250,506 B | **0.61x** |
| mm≥2 | 745 | 14,020 B | 58 B | **241.72x** |
| ALL | 2458 | 165,876 B | 165,742 B | 1.00x |

Sampling with replacement concentrates common shapes harder than the data does,
so the mm==1 arm produces *more* than reality and pins the aggregate near 1.00x
whatever the shape function does.

*(b) `> 1.5` could not fail for the case it exists to catch.* On mm≥2:

```
this key (Symbol admitted)      241.72x
pre-W4-F key (Symbol dropped)     3.83x
refuted first draft (Opaque)      3.77x
SABOTAGE: opcode only, no args    1.87x   <- would PASS at 1.5
```

**The rewritten control scores the defective keys below its own threshold**, which
the old one did not — that is why this is a repair and not goalpost-moving. The
bar is now ≥10x **and** ≥3x a degenerate opcode-only key recomputed on the same
rows, so it cannot be quietly tuned; the mm==1 and whole-population arms are
printed as information, explicitly labelled vacuous.

⚠ And **the pre-lane 1.30x was not health** — it was the artifact family inflating
the *observed* side deterministically while the null spread those rows by
probability. A number moving from 1.30 to 1.00 here is the instrument getting
*more* honest, not the ranking getting worse.

## Item 2 — `scripts/atexit_fuzzy_verify.py` retired

### Mechanism and the verified redundancy

Lane ATEXIT-RULER (`13015e35`) found the tool driving objdiff on a hardcoded
`-c functionRelocDiffs=none` and writing `verdict=COMPLETE` — a permissive ruler
closing rows — and recorded that its only unique capability was that false
promotion.

**The redundancy claim, verified rather than inherited:**
`scripts/sync_match_percent.py --promote` keys on `report.json`'s own
`fuzzy_match_percent == 100` (lines 103, 363) for **every** symbol with no `??__F`
exclusion, and guards `IDENTITY_UNESTABLISHED`. It is graded by construction, and
the patcher the tool chased is a wired post-compile ninja step, so `report.json`
already reflects patched objects.

**Blast radius zero, re-verified with an ESCAPED `LIKE`** (`_` is a single-char
wildcard in SQLite; read-only against main's `decomp.db`, since the worktree's is
a 0-byte file):

```
verdict_reason='atexit_fuzzy_scope_match' : 0
verdict_reason='atexit_relocation_noise'  : 0
VACUITY GATE: 680 rows carry a non-null verdict_reason across 100 distinct values
??__F rows, ESCAPED LIKE: 13    unescaped (wildcard, wrong): 125
```

The escaping is not pedantry — it changes the answer by ~10x.

### What happened to the motivating row

**`??__FsFrames@@YAXXZ` no longer exists in `report.json` at all** (55 `??__F`
rows now, 56 at the ATEXIT-RULER lane). Of the 52 sub-100 `??__F` rows, **49 sit
at `fuzzy=0.000` in `auto_*` units** — unpairable, promotable by nothing. Only 3
are live: `TheLocale` 49.375, `sLoadedFile` 97.571, `sBloom` 80.000.

### The two capabilities, handled explicitly

**1. WITHHELD report — KEPT, as `tools/shape_families.py --withheld`.** This is
the part worth keeping, because it is what made the `??__FsFrames` wrong-callee
class visible instead of silently dropped. Generalised three ways:

* **whole binary** instead of 56 `??__F` rows — **1,973 rows / 450,752 B /
  4.3993 pp of `total_code`**, ~35x the coverage;
* **one ruler** instead of two — a row whose every charge is a relocation-name arg
  reads 100 under `none` *by construction*, so the old control leg bought nothing;
* **it names the callee pair**, where the old report printed only percentages, and
  it flags a target that is already an alias-group **survivor** as `fold-suspect`.

It says, in the output, that these are candidates and must never be closed from
the list.

It immediately surfaced a class no percentage could: **`?Handle@PlatformMgr@@` has
target and base calling a *permutation of one callee set*** (`InviteUserParty` ↔
`ShowUserFriendsUI`, `ShowOfferUI` ↔ `ShowUserPartyUI`) — a message-dispatch
**order** divergence, which no fold can explain. `?Handle@OvershellPanel@@` shows
the same shape across `ConnectionStatusChangedMsg` / `ServerStatusChangedMsg` /
`NetStartUtilityFinishedMsg`.

**2. `--mark-at-limit` — DELIBERATELY NOT PORTED.** It stamped `AT_LIMIT` (a
**floor certification**) on `fuzzy >= 95` atexit rows with
`verdict_reason='atexit_relocation_noise'` — bit-for-bit the label **MPNGAP-1
refuted**: *"an `AT_LIMIT` label on a row whose only penalties are
relocation-name args carries no information — it is the detector restating its own
input."* **0 rows ever carried that reason.** Porting it would re-arm a
vein-closing verdict nobody had used. Recorded in `TECHNICAL_NOTES.md`,
`VERDICT_STATES.md`, and at the removed test in `test_verdict_identity.py`.

### The briefed blast radius was too small — 7 consumers, not 3

Beyond `test_verdict_identity.py` and VERDICT_STATES' two write-seam lists:
`scripts/orchestrator/test_atexit_ruler.py` (a whole 265-line file),
`scripts/analysis/ruler.py`'s `_CONSUMERS` guard tuple, `TOOLING.md`'s inventory
row, and `TECHNICAL_NOTES.md`'s runnable recipe (which **instructed `--apply`** —

### The retirement STRENGTHENS a guard instead of losing one

`test_atexit_ruler.py`'s most durable assertion, `test_no_hardcoded_ruler_in_source`,
applied the right check to exactly **one** of `_CONSUMERS`' five entries. Rather
than delete it with its subject it is generalised in
`scripts/test_ruler_consumers.py` (3 tests) to **all** entries, plus
`test_every_listed_consumer_exists` — **which caught this very commit** leaving the
retired tool in the tuple (2/3 red until `ruler.py` was updated) — plus a
must-be-able-to-fail arm proving the regex matches the defect it describes.

⚠ The tempting stronger gate, *"every file mentioning `functionRelocDiffs` must be
registered"*, is **measured infeasible**: **59** non-build `.py` files mention the

## Item 3 — `run_analyze_function`, an advertised MCP tool that could never run

**Mechanism.** Advertised in `list_tools` while its handler shelled out to
`<project_dir>/bin/analyze-function`. Verified rather than assumed: no such path,
and **`git log --all -- bin/analyze-function` is empty** — no commit ever added or
deleted one. The advertisement was ported from DC3, which *does* have both
`bin/analyze-function` and `tools/analyze_function.py`, without the tool. Every
call returned `Error: analyze-function not found` **after** the model had paid to
select it. A dead advertisement is worse than an absent one: the model cannot tell
the difference until it has spent the call — and the description promised the most
attractive thing in the list ("detailed diff with field names for offset
mismatches").

**Wiring was considered and rejected, with reasons:** DC3's implementation is
**2,657 lines**, imports `requests` to drive a **live Ghidra MCP HTTP service**,
and carries DC3-specific objdiff asm-format compatibility branches ("pre-fdc5113
flat comparison-join"). Its capability is already covered here by
`run_diff_inspect` (modes `offsets`/`diagnose`) plus `lookup_struct_offset`. And
its headline promise is served in DC3 by the **struct DB**, whose offsets come
from hand-written `// 0xHEX` comments CLAUDE.md records as measurably wrong
(CharEyes.h: 20 wrong offsets; SaveLoadManager.h: uniformly +4 stale) —
`lookup_struct_offset` was deliberately moved to ask the **compiler** for exactly
that reason, so resurrecting the tool would walk that fix backwards. The reasoning
is recorded in place, where the handler was.

**The guard.** `scripts/orchestrator/test_advertised_tools.py` (6 tests) reads
`mcp_server.py` with `ast` rather than importing it — the module needs the `mcp`
package and a DB, and **a test that needs a live server is a test that gets
skipped**, which is how this survived. It checks both directions (advertised with
no handler; handler with no advertisement = dead code), advertisement uniqueness,
and that no handler references a `bin/<x>` absent from the repo.

Anti-vacuity: `test_the_extractors_are_not_vacuous` floors both AST extractors at
8 and requires a known-live tool in each — extractors that silently return `[]`
would make every other assertion pass.

**Scripted sabotage over three mutations of the real file: 3/3 caught by the
intended test**, each rc=1 — advertised-without-handler → 
`test_no_advertised_tool_lacks_a_handler`; handler-without-advertisement →
`test_no_handler_is_unreachable`; a reintroduced `bin/analyze-function` reference →
`test_no_handler_shells_out_to_a_missing_repo_executable`.

## What I did NOT do

  (`SyncProperty`, `SystemLocale`/`SystemLanguage`, `CriticalSection`/`Task`
  `operator new`, the `?Handle@` dispatch-order family) is left as a handoff. This
  was a tooling lane; closing one of those needs retail-byte evidence.
* **Did not run an `ab_measure` A/B.** No `src/`, `config/`, `configure.py`, CI or
  patcher file is touched, so no byte can move. `total_code` is read, never
  written.
* **Did not port `--mark-at-limit`** — argued above, with the MPNGAP-1 citation.
  If someone wants it, the honest form is a *report*, not a verdict writer.
* **Did not port DC3's `analyze_function.py`** — 2.6 kLOC, live-service
  dependency, capability already covered.
* **Did not add the `functionRelocDiffs`-mention coverage gate** — measured
  infeasible (59 mentions vs 5 consumers).
* **Did not touch the shared diff cache** at `~/tmp/crossing_worklist/diffs`, and
  did not delete my worktree.
* **Did not fix `structural_decompose`'s empty transposed population.** 0 ALL /
  0 SOME is a legitimate state of a drained class, not a defect; the selftest no
  longer treats it as one.
* **Did not re-run the whole-binary `crossing_worklist` census** to see whether
  the fixed key changes *its* output — it does not consume these keys, so it
  cannot. Unverified only in the sense that I did not prove the negative.
* **Left the 6 stale known-bad entries alone** (`unicorn_runner` comparator
  tests). They are unrelated to this lane and dropping lines from
  `test_tools_known_bad.txt` is someone's deliberate call.
