## (b) Strategic read: grind vs TU5 vs OSS-build

**1. The matching grind has hit hard diminishing returns as the *primary* investment.**
Marginal cost is now ~1M tokens per +4 strict. The remaining classes are real but
expensive (each needs a dedicated session or new tooling, not a wave). Continuing to
lead with grind buys percentage points nobody consumes — the base/TU0 binary has
**no downstream consumer**.

**2. TU5 is where all the value pointers converge.** RB3Enhanced, the
same-instrument patch, and actual players all run TU5 (v0.0.5.1). The re-base is
cheap by construction: the expensive layer (matched `src/`, `objects.json`,
`decomp.db` names) is name-keyed and survives untouched; only the machine-generated
VA-keyed layer (splits/symbols/maps/evidence JSON) regenerates, and the map that
drives that regeneration is already built and validated. The changed-set is small
and sized: 478 total, of which only **81 MISS bodies** are genuine decomp work — and
those 81 are exactly the TU5-era game fixes, i.e. the game-code-first priority from
CLAUDE.md made concrete. **The 81-body P5 worklist is the natural successor to the
exhausted wave cadence.**

**3. The OSS/no-XDK thread is complete, not pending.** Its purpose (build the
same-instrument TU without the XDK) was achieved: `cl.exe /c` under wibo + the
`objcave_pack.py` packer + `.patch.toml` delivery. Path 2 (full DLL rebuild,
PE→XEX2 forward packing) remains a documented fallback for upstreaming only — do
not invest until there's a concrete upstreaming decision.

**Timing note:** the wave cadence being closed is precisely what makes the re-base
safe *now* — no in-flight wave lanes are mutating `splits.txt`/`symbols.txt`/
`target_symbol_map.json`, so the atomic flip has a natural low-conflict window.
This window should be used before any new deep-grind session reopens edits to the
VA-keyed layer.

## (d) TU5 re-base: **GO**, with sequencing

**Verdict: GO — full re-base, commit to main.** Rationale: (i) all consumers are on
TU5; base/TU0 has none. (ii) The portability split is proven — work product is
name-keyed and survives; only the machine layer regenerates, driven by an
already-built, validated 94.3%/96.4% map. (iii) The changed-set is bounded and
enumerated (478, of which 81 real). (iv) Dual-target and overlay were already
evaluated and rejected for cause (double CI, no clean delta). (v) The closed wave
cadence gives a uniquely cheap freeze window.

**Sequencing (order is load-bearing):**
1. **Boot test first** (action #1). If the `.data` cave fails to execute, the cave
   strategy needs rework *before* the patch ships — but this does NOT block the
   re-base itself (steps 2–5 proceed regardless).
2. **Land keystone artifacts additively** (action #2). TU0 stays the build target;
   nothing regenerates yet. Tag state (TU0 already frozen at `target/tu0-frozen`).
3. **Freeze declaration:** no agent edits `splits.txt` / `symbols.txt` /
   `target_symbol_map.json` / `config.yml` in main until the flip lands. Enforce by
   announcement + a marker file; keep the window short (days).
4. **P2–P4 in the worktree** with the match-floor gate. Pre-compute the expected
   floor: 15,822 minus matched functions that map into the AMBIG/MISS set (derive
   the exact number from the map BEFORE the flip so any drop is fully explained).
5. **Atomic flip commit** to main: TU5 xex becomes `orig/45410914/default.xex`'s
   role (or config re-point), regenerated splits/symbols/maps land together,
   `report.json` regenerates, `decomp.db` re-ingested. One commit, one landing.
6. **P5 changed-set decomp** (action #4) as the new standing worklist.

**NO-GO reversal condition:** if P4's re-verify shows an unexplained (not
changed-set-localized) match loss > ~1% of the 15,822, halt the flip, keep main on
TU0, and debug the map — the worktree structure makes this a free rollback.

### Pre-computed match FLOOR (step-4 gate, computed 2026-07-12 — Opus)

Symbol-intersection of our **15,816 matched** functions (report.json, norm 100%)
against the **478-entry changed worklist** (`tu5_changed_worklist.json`):

| bucket | worklist | of which WE currently match | disposition on flip |
|---|---|---|---|
| **MISS** (skeleton-*changed* — genuine body diff) | 81 (45.7 KB, 33 >256 B) | **48** | **drop → become the P5 worklist** |
| **AMBIG** (skeleton-*present*, unplaced — mapping ambiguity, body unchanged) | 397 | 173 | re-anchor & survive; only 27 are ≥256 B needing real disambiguation (306/397 are <128 B leaves) |

- **Guaranteed floor = 15,816 − 48 = 15,768** (only the genuine body-changes drop).
- **Absolute worst case = 15,816 − 221 = 15,595** (if *every* AMBIG-hit also fails
  to re-anchor — implausible; most are tiny identical leaves).
- **Every dropped function is enumerated in advance**, so any P4 loss inside this
  set is *explained* by construction. The NO-GO trips only on losses *outside* it.
- **Conclusion: the flip clears its own gate before it runs.** Realistic net cost
  ~48–70 matches (≤0.45%), and those 48→81 MISS bodies are precisely the
  TU5-era game-code changes = the highest-value decomp targets (CLAUDE.md
  game-first priority) that seed P5. This is a strong GO signal, not a risk.
